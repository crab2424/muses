# muses ステージ背景 r1 — 設計（2026-09-30）

ユーザー要望: ステージの背景を描く。テーマは未定なので3案を提案し、ラボで比較してから Unity へ移植する。
参考画像2枚（白い天空の神殿／薔薇色の柱の回廊）は**内容ではなく形式**（中央の消失点に向かう対称構図、
奥を暗く抜く）の参考。

## 3. 画面の事実（Unity 既定 StageConfig: φ=77, yCam=8, θ=38, vGroundJudge=−0.75, vSkyJudge=0.15）

- **地平線 v=0.982（画面上端から0.9%）**。カメラは見下ろしているので、背景に写るのは「空」ではなく
  **ステージの左右と下（眼下）にあるもの**。空はほぼ写らない。
- z_judge=3.10, **z_far=78.4**, 空中面の高さ 6.12。
- 地上面（groundFillAlpha=1）は不透明で画面の下〜中央の台形を覆う。空中面は alpha 0.2 で背景が透ける。
  → 背景が見えるのは**ステージ台形を挟む左右の V 字領域**（参考画像1の逆三角の構図と同じ形）。
- 最遠端の断面（ノーツ出現位置）: 地上の奥 v=0.791、空中の奥 v=0.935、横幅 u=±0.096。

## 4. 暗部の仕様（ノーツ出現位置の視認性）

- **暗部ゾーン** = 最遠端の断面（u ±0.096、v 0.791〜0.935）に余白（横0.06・上0.08・下0.02）を足した画面座標の長方形
  → u ±0.156、v 0.771〜1.0。`design-lab/stage-bg/shared/zone.js` が正。θ等が変わっても最遠端から再計算する。
- **基準（暫定）**: 背景のみ（ステージ・ノーツなし）を描いたときの、ゾーン内の相対輝度（Rec.709、linear）が
  **平均 ≤ 0.06、95パーセンタイル ≤ 0.12**。ラボが0.5秒ごとに計測して各タイルに表示する。
  参考: 現行の単色 #a0b298 は 0.416（基準の7倍）。
- **二段構え**: (1) テーマ自身が世界の中の物体（モノリス／幕／ゲート）で暗くする。(2) 最終保証として
  **全テーマ共通の暗幕**（ゾーン＋ぼかし14%を覆うスクリーン空間の板1枚、色と強さはテーマが指定）を背景の最後に描く。
  狙いは (1) だけでほぼ基準を満たし、暗幕は弱く（≤0.5）済むこと。

## 5. 制約（iPad で背景 1〜2ms 以内を目安）

- ポストプロセス（ブルーム等）なし。画像ファイルなし。起動時に手続き生成するテクスチャは2枚・512²まで（Unity では焼いて持つ）。
- 背景の draw call ≤ 10。**全画面の板は1枚まで**（背景の土台）。その上の半透明層は必要な範囲だけ覆う板にする。
  全画面シェーダーのノイズは4オクターブ程度まで。
- 粒子は1メッシュ（Points／InstancedMesh）で ≤ 500。
- 動きは遅く、点滅なし。暗部ゾーンの近くでは特に控えめにする（ノーツと見間違えないため）。
- **ステージの面の色（地上面・レーン線）はテーマから変えてよい**が、地上面は暗いまま（相対輝度 ≤ 0.10）にする。
  明るい地上面はノーツ（ネオン）の設計を変えるので今回の範囲外。
- 画面比 1.33〜1.5 のどれでも破綻しないこと。

## 6. ラボ

`design-lab/stage-bg/`（launch.json `design-lab`、http://localhost:5181/stage-bg/）。契約は同ディレクトリの README.md。
背景 → 共通の暗幕 → 深度クリア → ステージ＋ノーツ（note-skin のネオン／キーキャップをそのまま使う）の順に描く。

## 7. Unity 移植の見通し（案が決まってから詳細化）

- 背景は `StageController` のカメラのクリアを置き換える。背景用のメッシュとシェーダーを、ステージより前の renderQueue で描く。
- テーマ差し替え: `StageBackground` の ScriptableObject（またはプレハブ）1つ = 1テーマ。StageConfig にテーマ参照を持たせる。
- 暗幕: スクリーン空間の板1枚＋ゾーン計算（最遠端の投影）を C# に移植。
- ラボの `uFragToBase` / `uBaseToClip` はラボの拡大表示用なので、Unity では恒等（スクリーンUV×2−1）。
