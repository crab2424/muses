# muses ステージ背景 r1 — 設計（2026-09-30）

ユーザー要望: ステージの背景を描く。テーマは未定なので3案を提案し、ラボで比較してから Unity へ移植する。
参考画像2枚（白い天空の神殿／薔薇色の柱の回廊）は**内容ではなく形式**（中央の消失点に向かう対称構図、
奥を暗く抜く）の参考。

## 1. ユーザー決定（同日）

| 論点 | 決定 |

| 絵の作り方 | **手続き生成のみ**（three.js／シェーダー。画像素材なし） |

## 3. 画面の事実（Unity 既定 StageConfig: φ=77, yCam=8, θ=38, vGroundJudge=−0.75, vSkyJudge=0.15）

- **地平線 v=0.982（画面上端から0.9%）**。カメラは見下ろしているので、背景に写るのは「空」ではなく
  **ステージの左右と下（眼下）にあるもの**。空はほぼ写らない。
- z_judge=3.10, **z_far=78.4**, 空中面の高さ 6.12。
- 地上面（groundFillAlpha=1）は不透明で画面の下〜中央の台形を覆う。空中面は alpha 0.2 で背景が透ける。
  → 背景が見えるのは**ステージ台形を挟む左右の V 字領域**（参考画像1の逆三角の構図と同じ形）。
- 最遠端の断面（ノーツ出現位置）: 地上の奥 v=0.791、空中の奥 v=0.935、横幅 u=±0.096。

## 4. 暗部の仕様（ノーツ出現位置の視認性）

- **暗部ゾーン** = 最遠端の断面（u ±0.096、v 0.791〜0.935）に余白（横0.06・上0.08・下0.02）を足した画面座標の長方形
  → u ±0.156、v 0.771〜1.0。`design-lab/stage-bg/shared/zone.js` が正。θ等が変わっても最遠端から再計算する。
- **基準（暫定）**: 背景のみ（ステージ・ノーツなし）を描いたときの、ゾーン内の相対輝度（Rec.709、linear）が
  **平均 ≤ 0.06、95パーセンタイル ≤ 0.12**。ラボが0.5秒ごとに計測して各タイルに表示する。
  参考: 現行の単色 #a0b298 は 0.416（基準の7倍）。
- **二段構え**: (1) テーマ自身が世界の中の物体（モノリス／幕／ゲート）で暗くする。(2) 最終保証として
  **全テーマ共通の暗幕**（ゾーン＋ぼかし14%を覆うスクリーン空間の板1枚、色と強さはテーマが指定）を背景の最後に描く。
  狙いは (1) だけでほぼ基準を満たし、暗幕は弱く（≤0.5）済むこと。

## 5. 制約（iPad で背景 1〜2ms 以内を目安）

- ポストプロセス（ブルーム等）なし。画像ファイルなし。起動時に手続き生成するテクスチャは2枚・512²まで（Unity では焼いて持つ）。
- 背景の draw call ≤ 10。**全画面の板は1枚まで**（背景の土台）。その上の半透明層は必要な範囲だけ覆う板にする。
  全画面シェーダーのノイズは4オクターブ程度まで。
- 粒子は1メッシュ（Points／InstancedMesh）で ≤ 500。
- 動きは遅く、点滅なし。暗部ゾーンの近くでは特に控えめにする（ノーツと見間違えないため）。
- **ステージの面の色（地上面・レーン線）はテーマから変えてよい**が、地上面は暗いまま（相対輝度 ≤ 0.10）にする。
  明るい地上面はノーツ（ネオン）の設計を変えるので今回の範囲外。
- 画面比 1.33〜1.5 のどれでも破綻しないこと。

## 6. ラボ

`design-lab/stage-bg/`（launch.json `design-lab`、http://localhost:5181/stage-bg/）。契約は同ディレクトリの README.md。
背景 → 共通の暗幕 → 深度クリア → ステージ＋ノーツ（note-skin のネオン／キーキャップをそのまま使う）の順に描く。

## 7. Unity 移植の見通し（案が決まってから詳細化）

- 背景は `StageController` のカメラのクリアを置き換える。背景用のメッシュとシェーダーを、ステージより前の renderQueue で描く。
- テーマ差し替え: `StageBackground` の ScriptableObject（またはプレハブ）1つ = 1テーマ。StageConfig にテーマ参照を持たせる。
- 暗幕: スクリーン空間の板1枚＋ゾーン計算（最遠端の投影）を C# に移植。
- ラボの `uFragToBase` / `uBaseToClip` はラボの拡大表示用なので、Unity では恒等（スクリーンUV×2−1）。

## 8. r1 評価（2026-09-30、ユーザー）

- 3案とも「ノーツの視認性・暗部は問題なし、中身も申し分ない」。順位: **1. 神話の軌道都市 / 2. 天上の聖域 / 3. 黄昏の回廊**。
  **上位2つ（orbit・sanctuary）を Unity に実装する**（プレイヤーが選べる背景の候補、または曲/パックで切替）。
- r2 は軌道都市を詰める。**Sonnet 5.5 版（orbit-sonnet.js）と Opus 5.5 版（orbit-opus.js）を並べて比較**（元の orbit.js は r1 として残す）。
- 修正点:
  1. 奥の暗部（ゲート）が縦長の楕円に見える → **真円**に。原因: ワールドの垂直面に置いた円の中心が v=0.9 で上半分が画面外に切れ、
     左右の弧だけが見えていた。加えて都市側の沈め（角丸長方形マスク）の形が混ざっていた。
     → 共通化: `shared/zone.js` の `gateCircle()`（画面上の真円。円全体が画面内＝上端 v≤0.98、かつ最遠端の断面4隅を覆う。
     iPad 11" で中心 v=0.749・半径0.231（縦単位））と `GATE_GLSL`。
  2. 神殿のワイヤーが視点から崩れて見える → **ステージの方向（z軸）に沿わせて配置**（中央へのひねり・ヨーの揺れをやめる）。
  3. 負荷を重くしない範囲でアニメーションを追加。
- 線は `shared/lines.js`（画面上で一定幅の帯メッシュ、1 draw call）に統一。Unity に1px線が無いため、移植時もこのまま使える。

### r2 結果（2026-09-30）
- **ゲートの真円**: 円全体を画面内に収めようと中心を v≈0.75 に下げると、下半分以上がステージの台形の裏に隠れてドームに見えた。
  ステージは断面（v=0.79）より下で必ず円より広がるので、断面を覆う円の下部は必ず隠れる。→ `gateCircle` は
  **中心 = 断面の中央（v≈0.863）、半径 = 断面4隅までの距離（≈0.155）**。上端が約2%画面外、円の約7割が見え、ステージが門へ入る見え方。
  縁は断面の隅（ノーツの出現位置）を通るので、暗部ゾーン内では縁の明るさを 0.15 倍程度に落とす（両版とも）。
- **y<0 の物体の隠れ**: 視線が y=0 を横切る点が地上面（|x|≈7.3）の内側だと、不透明な地上面に隠れる。
- `shared/lines.js` の初版は帯の三角形が常に裏向きで全く描かれていなかった（修正済み、DoubleSide）。
- orbit-opus.js（Opus）: 神殿5棟×左右を長手 z でステージ脇（y=-6、ステージ端から9）に等間隔に並べた「天空の参道」。
  動き = 列柱をなぞる光が手前→奥へ伝わる行進（12秒）、大通りの車列、軌道リングの光点、ゲート内の同心円と縁の目盛り。draw 6、暗部 0.025/0.081。
- orbit-sonnet.js（Sonnet）: 神殿2棟×左右（大きめ・低い柱・水平面で読ませる）、ゲート内に同心リング5本と金の目盛り環、
  大通りを流れる光、浮遊足場の上下など。draw 9、暗部 0.032/0.094。

## 9. r2 評価 → r3（2026-09-30）

- ユーザー: 全体として **Sonnet 5.5 の軌道都市 r2（orbit-sonnet.js）が一番良い → これ1つに絞る**。
- ゲートは「真円」の意味の取り違えがあった。望みは **r1 のゲートのデザインそのまま（ステージ幅を超え上部が画面外にはみ出す大きさ、
  同心リングを足した動かない円）を真円にするだけ**だった（gateCircle による断面基準の小さな円・吸い込まれる同心リングは不要）。
- r3 = `themes/orbit-r3.js`（r2 を土台に Opus が調整）:
  1. ゲート = r1 の寸法（中心 NDC(0,0.9)、半径 = 横0.23 = 縦単位 0.23×aspect）と中身（黒い円盤・縁・外側の2本目・同心リング3本、静止）を
     スクリーン空間の板で真円に。暗部ゾーンは円盤に完全に収まるので**共通の暗幕なし**（計測 0.003 / 0.010）。
  2. r2 で左右に浮いていた時計盤のリング（主環・内環・金環・36目盛り・光点3つ）を**ゲートの外周**へ。主環と目盛りは約3分で1周、金環は逆回転の破線。
  3. 神殿（z=-46/-100 → -26/-66）と浮遊足場を手前へ。最前の神殿は画面外にはみ出す（ユーザー許容）。左右の傾いたリングは削除。
  4. 都市の灯り（密度 0.6→0.35 等）・碁盤・道路の明るさを下げ、神殿の線を少し強く（opacity 0.9）。
- draw 6（都市・ゲート・神殿・足場×2・粒子）。3画面比で暗部 平均0.003 / p95 ≤0.010。
