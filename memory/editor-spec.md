# muses 譜面エディタ仕様（Phase 4 / 2026-07-31 rev.1）

対象: 譜面エディタのファイル形式・UI・操作・検証・プレビュー・保存。
関連: `note-spec.md`（ノーツ仕様。本書はその §9.5「エディタ要件」の展開でもある）、
`implementation-roadmap.md`（Phase 4 の位置づけ）、`unity-stage-port-design.md`（ステージ座標系）。

---

## 0. 方針（確定）

- **デプロイ不要**。PC（Mac / Windows）で動けばよく、タブレット実機で動く必要はない。
- **ゲームとエディタは別物として考える**。プレイ画面にエディタ UI を重ねる「エディタモード」は作らない。
- **実装基盤は Unity Editor 拡張**（`unity/Assets/Editor/` の `EditorWindow`）。
  **Why**: `Chart/ChartNote.cs`・`ChartFormat.cs`・`ChartMath` など既存の C# ロジック
  （tick→秒変換、コンボ点生成、判定トレイト表、easing）を**そのまま参照できる**ため、
  二重実装と仕様のズレが構造的に起きない。Mac / Windows 対応は Unity Editor 自体が担保する。
  「ゲームとは別」は**実行時の分離**（Play モードのゲームと編集用ウィンドウが混ざらない）で満たす。

## 1. ファイル形式

### 1.1 なぜ JSON でないか

ノーツは**同質なレコードの列挙**で、フィールド数も固定に近い。この形は
「1レコード＝1行、列を桁揃えした表」が最も読みやすく、`{}` の入れ子はノイズにしかならない。
加えて**1ノーツ＝1行なので Git の差分がそのまま意味を持つ**（JSON の配列だと
1個の挿入で以降の整形が揺れうる）。よって**行指向の表形式テキスト＋独自拡張子**とする。

**圧縮しない。** 曲・ジャケットとのセットは zip ではなく**フォルダ**で持つ。
zip はテキストエディタからも Git からも中身が見えなくなり、「可読性優先」の判断基準に反する。
配布・受け渡しのときだけ外側で zip に包めばよい。

### 1.2 フォルダ構成

```
songs/
  <song-id>/
    song.muses        曲メタ（タイトル / 音源 / ジャケット / オフセット / 拍子 / BPM）
    line.muses        難易度ごとの譜面（ノーツ + scrollEvents）。難易度名は §1.7
    square.muses
    cube.muses
    audio.ogg         音源は **ogg 固定**（確定）
    jacket.png
```

**曲メタと譜面を分離する。Why**: BPM マップは曲の属性であって譜面の属性ではない。
難易度ごとに複製すると、BPM を1箇所直したときに他が古いまま残る同期ズレが起きる。
分離すれば BPM 修正が全難易度へ自動的に反映される。

### 1.3 字句規則（両ファイル共通）

| 要素 | 記法 |
|---|---|
| ヘッダ命令 | `@KEY 値`（値はキー以降**行末まで**。タイトル等の空白を含む値をそのまま書ける） |
| セクション | `[NAME]` |
| コメント | `#` から行末まで |
| 列区切り | 1個以上の空白またはタブ（**桁揃えは自由**） |
| 省略 | 既定値の列・オプションは書かなくてよい |

- 文字コードは **UTF-8 (BOM 無し)**、改行は **LF**。
- パーサは空白量に寛容だが、**エディタが書き出すときは列を桁揃えする**（人が読む前提のため）。
- 書き出し順は **addr → layer → cell の昇順に正規化**する。
  **Why**: 同じ譜面なら常に同じバイト列になり、Git の差分が編集内容と一致する。

### 1.4 時刻表記 `bar:beat:tick`

生の累積 tick（例 `161280`）は人が読めないので、**小節:拍:tick** で書く。

- `bar` は 1 始まり、`beat` は 1 始まり、`tick` は `0 … ticksPerBeat-1`（= 0…5039）。
- 例: `5:3:1260` = 5小節目 3拍目 の 16分1つ分あと。
- 累積 tick との変換は拍子（§1.5 `[METER]`）から一意に決まる。**ロード時に累積 tick へ、
  保存時に `bar:beat:tick` へ**変換する。ランタイムのデータモデル（`Waypoint.tick`）は
  累積 tick のまま**一切変更しない**。

> **`[METER]`（拍子）は note-spec.md に無い新概念**。小節グリッドの描画と本表記に必要なため
> エディタ層で導入する。`ChartData` には入らず、tick↔addr 変換にのみ使う。

### 1.5 `song.muses`

```
@FORMAT   muses-song 1
@TITLE    サンプル曲
@ARTIST   だれか
@AUDIO    audio.ogg
@JACKET   jacket.png
@PREVIEW  32.0 45.0        # 試聴の開始秒 終了秒
@OFFSET   -0.024           # 音源先頭 → 譜面 tick 0 のズレ(秒)

[METER]
# bar   拍子
  1     4/4
  33    3/4

[BPM]
# addr        bpm
  1:1:0       150
  33:1:0      180
```

- `@AUDIO` は **ogg 固定**（確定）。Unity のインポート設定は Vorbis / Streaming を既定とする。
- `@OFFSET` は**譜面と音源の頭合わせ**であり、`StageConfig.judgeOffsetMs` /
  `visualOffsetMs`（プレイヤー個人の環境補正、`PlayerPrefs` 保存）とは**別物**。混同しないこと。
- `@PREVIEW` は**開始秒と終了秒の2値のみ**。曲選択画面（Phase 5）が無い現段階では
  **読み書きするだけで使わない**（形だけ実装）。
- `[METER]` の既定は `4/4`。省略時は全編 4/4 とみなす。
- `[BPM]` は `ChartData.bpmEvents` にそのまま対応。1:1:0 のエントリが無ければ既定 120。

### 1.6 `<difficulty>.muses`

```
@FORMAT     muses-chart 1
@SONG       song.muses
@DIFFICULTY CUBE
@LEVEL      13
@CHARTER    crab2424

[SCROLL]
# addr        grp  mul    options
  1:1:0       0    1.0
  17:1:0      0    2.0    dur=5040 ease=sineout
  17:1:0      1    0.0

[NOTES]
# addr        kind    layer  cell  width  options
  5:1:0       tap     G      3     1
  5:1:1260    extap   S      7     1
  5:2:0       flick   G      0     2
  5:3:0       slide   G      2     2      grp=1
    >  5:4:0          G      4     2      ease=smooth
    >  6:1:0          S      6     1      mark=vis
  9:1:0       tap     0.5    5     1
```

**`[NOTES]` の列**

| 列 | 内容 |
|---|---|
| `addr` | §1.4 の `bar:beat:tick` |
| `kind` | `tap` / `extap` / `slide` / `flick` |
| `layer` | `G` = layerF 0（地上）、`S` = layerF 1（空中）、中間値は生の float（`0.5`） |
| `cell` | `cellF`（帯の左端。Slide は §5.4 のとおり**中心基準**ではなく他と揃えて左端） |
| `width` | 幅（セル数、float） |
| `options` | 下表のうち既定でないものだけ書く |

**オプション**

| キー | 対応フィールド | 既定 |
|---|---|---|
| `grp=N` | `Note.scrollGroup` | 0 |
| `ease=` | `Waypoint.easing`（`linear`/`smooth`/`sinein`/`sineout`/`sineinout`/`quadin`/`quadout`） | `linear` |
| `mark=` | `Waypoint.marker`（`vis` / `invis`） | `none` |
| `combo=N` | `Waypoint.comboStep`（tick） | 自動（null） |

**Slide の継続行**: `>` で始まる行が 2 点目以降の Waypoint。`kind` 列を持たない。
始点行の `ease` / `mark` / `combo` も options としてそのまま書ける。
`grp` は**ノーツ単位**なので始点行にのみ書く。

**`[SCROLL]` の列**: `addr  grp  mul  [dur=N ease=...]`。`ScrollEvent` に 1:1 対応。
`dur` の既定は 0（階段状）。

### 1.7 難易度名（確定）

**次元の名前を使う。** 難易度が上がるほど次元が増える。

| `@DIFFICULTY` | 次元 |
|---|---|
| `LINE` | 1次元 |
| `SQUARE` | 2次元 |
| `CUBE` | 3次元 |
| `TESSERACT` | 4次元（**上位難易度として後から追加する枠**。常設ではない） |

- **基本は 3 段階**（`LINE` / `SQUARE` / `CUBE`）。`TESSERACT` は曲によって追加する。
- ファイル名は難易度名の小文字（`line.muses` / `square.muses` / `cube.muses` / `tesseract.muses`）。
- `@LEVEL` は数値表記で別に持つ（難易度名とレベル値は独立）。

## 2. 画面レイアウト

単一の `EditorWindow`（メニュー: `Window > muses > Chart Editor`）。

```
┌─ ツールバー ───────────────────────────────────────────────────┐
│ 開く 保存 | ▶ ⏸ ■ | 速度 1.0x | snap 1/16 | 幅 1 | 位置 12:3:0 | [検証] | ● 未保存 │
├────────┬────────────────────────────────────┬──────────────┤
│ ツール   │        ノーツシート（主キャンバス）              │  3Dプレビュー  │
│ パレット  │  時間ルーラ │ Ground 12セル │ガタ│ Sky 12セル    │              │
│         │                                              ├──────────────┤
│ 選択情報 │                                              │ インスペクタ   │
│         │                                              │ (選択ノーツ)   │
├────────┴────────────────────────────────────┴──────────────┤
│ 波形 + イベントレーン（BPM / scroll×グループ / 小節番号）                      │
├──────────────────────────────────────────────────────────┤
│ 検証結果リスト（[検証] 実行時のみ展開）                                       │
└──────────────────────────────────────────────────────────┘
```

### 2.1 ノーツシート（主キャンバス）

- **縦軸 = 時間**。下が過去、上が未来（ゲームの奥行き方向と一致）。ホイールでスクロール。
- **横軸 = `cellF`**。`[Ground 12セル][ガター][Sky 12セル]` の2ペインが**同じ時間ルーラを共有**する。
  **Why**: プレイフィールドは `cellF × layerF` の2次元で、時間を足すと3軸になり必ずどこかを
  投影する必要がある。`layerF` は実運用でほぼ 0 か 1 の二値なので、そこをペイン分割に使うのが
  情報の損失が最も少ない。
- **ガター**（2ペイン間の細い帯）は `layerF` の中間値の居場所。層をまたぐ Slide の帯は
  ここを横断して描かれる。中間値のノーツはガター上に描き、正確な値はインスペクタで編集する。
  **当面は軽い実装で足りる**（中間値は実運用でほぼ使わないため）。ただし将来
  **「横からの投影」ビュー**（縦=時間、横=`layerF` にしてセルを潰した側面図）を
  追加する可能性があるので、**キャンバス描画・ヒット判定を「時間軸 × 任意の空間軸1本」で
  一般化しておき、`cellF` 決め打ちにしない**こと（§9-1）。
- **グリッド線**: 小節線（太）／拍線（中）／スナップ分割線（細）。分割はツールバーの
  `snap` に連動（`1/4, 1/8, 1/12, 1/16, 1/24, 1/32, 1/48, 1/64`）。セル境界線 12 本を縦に引く。
- **バンド境界線の表示は任意（既定 OFF）**。`vBandGround` / `vBandSky` の目視確認用。
  **バンドは入力を細分化して枠内更新を発生させるためだけの内部概念で、
  ノーツ配置には一切関与しない**（note-spec §0.1）。エディタでも表示専用で、
  スナップ対象にもクリック判定にもしない。

### 2.2 3D プレビュー

- 実ゲームと同じ `StageView` / `NoteView` を **`RenderTexture` に描画してウィンドウ内に埋め込む**
  （両者とも既に `[ExecuteAlways]` なので Play モードに入らず描ける）。
- **負荷対策を前提とする**。ここを常時再描画すると、Play 中に Game view の VSync を
  切っていたときと同じ「無制限レンダリングによる発熱」が編集中ずっと起きうる
  （[[muses-unity-port-progress]] で実際に踏んだ問題）。したがって:
  - **再生中のみフレーム更新**し、停止中は**譜面かカーソル位置が変わったときだけ**描き直す。
  - 更新レートに上限（例 60fps）を設ける。`RenderTexture` の解像度もパネル実サイズに留める。
  - パネルを畳んでいる間は `Camera.Render()` を呼ばない。
  - **これで重ければ採用を取り下げ、別ウィンドウ方式か、プレビュー自体の省略に切り替える**
    （ユーザーの採用条件が「重くならないなら」であるため）。
- 現在位置（`songTime`）をノーツシートと共有。ソフラン・hiSpeed の効き方もここで確認する。
- **編集は行わない**（選択ノーツのハイライト連動のみ）。ノーツ素材・判定演出・SE の確認場所。
- ノーツシートと同じ snap 分割のグリッド線を、ステージ上にもオプションで重ねられる
  （「その刻みが実際どう見えるか」の確認用）。

### 2.3 波形 + イベントレーン

- 音源のピーク波形（オフセット合わせ・BPM 合わせ用）。
- 上に BPM 変化点、scrollEvent（グループごとに 1 レーン）、小節番号を重ねる。
- クリックでシーク。

## 3. 配置・編集操作

### 3.1 ツールパレット

`選択` / `Tap` / `ExTap` / `Slide` / `Flick` / `Waypoint 追加` / `削除`

### 3.2 配置

- 左クリックで配置。tick は常に `snap` にスナップ。
- **Tap / Ex Tap**: `cellF` は**整数セルにスナップ**（判定が離散のため。note-spec §1.1）。
  幅はツールバーの既定幅。
- **Slide**: 始点クリック → 終点クリックで 2 点生成。以降 `Waypoint 追加` で中継点を挿入。
  `cellF` と `width` は **0.5 / 1.0 セル刻みにスナップ**（note-spec §1.1）。
- **Flick**: 操作は Tap と同じ。判定は連続座標だが既定は整数スナップ。
- `layerF` はクリックしたペイン（Ground / Sky / ガター）で決まる。

### 3.3 編集

- ドラッグで移動、ノーツ端のドラッグで幅変更、Waypoint のドラッグで形状変更。
- 矩形選択・複数選択。
- コピー / ペースト（ペースト位置の tick オフセット付き）。
- **一括変換**: 左右反転（`cellF → cells - cellF - width`）、層反転（`layerF → 1 - layerF`）、
  時間方向の平行移動、選択範囲の伸縮（tick の一様スケール）。
- **インスペクタ**: Note 単位（`kind` / `scrollGroup`）と Waypoint 単位
  （`tick` / `layerF` / `cellF` / `width` / `easing` / `marker` / `comboStep`）を数値で直接編集。
- Slide のコンボ点（`ChartFormat.ResolveSlideComboPoints` の結果）を**シート上に重ねて表示**する。
  自動生成の刻みが意図どおりかを目で確認できるようにするため。

## 4. 検証（バリデータ）

**常時実行しない。** ツールバーの `[検証]` ボタンで任意のタイミングに実行し、
**保存時にも自動実行する**（設定で OFF 可）。結果はウィンドウ下部にリスト表示し、
行をクリックするとその位置へジャンプする。

**Why 常時にしないか**: 編集途中は一時的に不正な状態を経由するのが普通で、
常時警告は編集の邪魔になる。

| ID | 種別 | 内容 | 根拠 |
|---|---|---|---|
| V1 | 警告 | BPM が変化する tick をまたぐ Slide に、その境界の Visible 中継点が無い | §2.3 |
| V2 | 警告 | `comboStep` 上書きを持つ Waypoint の `marker` が `Visible` でない | §2.3 |
| V3 | 情報 | 同一層でセル範囲が交差する同時刻ノーツ → **ハイライト表示**（禁止ではない） | §6.4 |
| V4 | エラー | Slide の points が 2 点未満 / Tap・ExTap・Flick が 2 点以上 | §1.1 |
| V5 | エラー | Waypoint の tick が昇順でない |  |
| V6 | 警告 | `cellF` / `cellF + width` が `[0, cells]` の外 |  |
| V7 | 警告 | `layerF` が `[0, 1]` の外 |  |
| V8 | 情報 | 縦連判定の実効窓が極端に狭い箇所（同一層・セル範囲交差で間隔 < 66.7ms → PERFECT 消滅） | §6.2 |
| V9 | 警告 | 同一 `(tick, group)` に scrollEvent が重複 | §5.5 |
| V10 | 情報 | 譜面末尾が音源長を超える |  |
| V11 | 情報 | 総コンボ点数（= スコア式の `N`）の表示 | §7 |

**実装場所**: `Chart/ChartValidator.cs` として**ランタイム側**に置き、Editor から呼ぶ。
**Why**: `UnityEngine` 非依存の純粋 C# にしておけば、`dotnet run` のスクラッチ検証
（[[muses-unity-port-progress]] で確立した手法）がそのまま使える。

## 5. プレビュー再生

### 5.1 音源同期プレビュー（判定なし）

- 任意位置から再生・一時停止・シーク。`SongClock.Seek/Pause/Resume` と
  `Judge.Seek`（Phase 3 で実装済み）をそのまま使う。
- 再生速度 0.25x 〜 2.0x。**ピッチは保持しない**（そのまま変わる）。譜面確認には支障なしと判断。
- メトロノーム ON/OFF（`SongClock` が既に持つ）。
- **ノーツ SE のプレビュー**: 判定を通さず、各ノーツの時刻ちょうどに SE を鳴らす。
  「譜面が曲に合っているか」を耳で確認するための機能で、判定の正しさとは無関係。

### 5.2 オートプレイ（簡易判定）

実ゲームの `Judge` をそのまま走らせ、**入力を自動生成**して全 PERFECT+ を狙う。
目的は判定系の回帰確認と、判定演出の確認。

- **実装は容易**。Phase 3 の改修で `Judge` は `NoteView` / `TouchInputManager` 依存を捨て、
  コンストラクタが `Action<NoteRuntime,float>`、`Update()` が `IEnumerable<Contact>` を
  受け取る**純粋 C# クラス**になっている。オートプレイ用の `Contact` 生成器を差し替えるだけで済む。
- **生成規則**:
  - Tap / Ex Tap / Slide 始点は**枠内更新（`EnterEvent`）が要る**ので、直前フレームは枠外に置き、
    当該フレームで枠内へ移動させる。
  - Flick は直近 `flickWindowMs` 内に `flickDistance` 以上の移動を作る。
  - Slide 継続は各コンボ点の位置を連続追従させる。
- **期待結果は理論値ちょうど 1,010,000**（note-spec §7）。ここからずれたら、判定か譜面の
  どちらかに異常がある。**エディタから回帰検知ができる**のがこの機能の主目的。

## 6. Undo / Redo・保存・自動保存

### 6.1 Undo / Redo

Unity 標準の `Undo.RecordObject` は `UnityEngine.Object` 前提で、`ChartData` は素の C# クラス
なので**使えない**。**独自の Undo スタックを持つ。**

- 方式は**スナップショット**（操作前後の `ChartData` をシリアライズ文字列で保持）。
  コマンドパターンより実装が単純で、**操作の取りこぼしが構造的に起きない**。
- **§1 のシリアライザをそのまま流用できる**ので二重実装にならない。
- 数千ノーツでも 1 スナップショットは数百 KB 程度。履歴上限は 50〜100 手。

### 6.2 保存

- 上書き保存 / 名前を付けて保存。保存時に §4 の検証を実行（エラーがあっても保存は可能、警告のみ）。
- 未保存の変更をツールバーに表示し、ウィンドウを閉じるときに確認する。

### 6.3 自動保存

- **n 分間隔（既定 5 分）で自動保存**。`EditorApplication.update` で経過時間を見る。
- 書き出し先は `<difficulty>.muses.autosave` で、**正規ファイルは上書きしない**。
  **Why**: 自動保存が壊れたデータを正規ファイルに書き込む事故を構造的に防ぐ。
- 変更が無ければ書かない。
- 起動時、autosave のほうが正規ファイルより新しければ**復元を提案する**。

## 7. 素材（ノーツ画像 / 判定演出 / ノーツ SE）の確認

ユーザーの要望により、これらを**エディタ内で確認できる**ようにする。ただし
**演出本体の実装は Phase 5** であり、エディタ側が用意するのは「差し替え先を選ぶ UI」と
「鳴らす / 出すトリガ」だけ。

- **ノーツ画像素材**: `NoteView` のマテリアル / テクスチャをエディタから切り替えて即確認。
- **判定演出**: オートプレイ中の実演出に加え、「指定のティアを今この位置で出す」テスト発火。
- **ノーツ SE**: §5.1 の SE プレビュー、および判定ティアごとの SE 差し替え確認。

現状、プロジェクト内に画像 / 音声アセットは 1 枚も無く、ノーツ描画は単色デバッグクアッドのみ。
