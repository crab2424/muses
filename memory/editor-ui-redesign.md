# muses 譜面エディタ UI 刷新 — 現状と参考画像の差分整理（2026-08-01）

`memory/editor-spec.md` rev.2 で定めた機能はひととおり実装済みだが、**見た目・操作感は
未調整のまま**（[[feedback-editor-ui-polish-deferred]] の方針でここまで指摘を溜めていた）。
ユーザーから参考画像として **MikuMikuWorld**（プロセカ系の譜面エディタ）のスクリーンショットが
提示されたので、実装に入る前に「具体的にどこがどう違うか」を洗い出す。

**このドキュメントは実装計画ではなく差分カタログ**。実装は別セッションで行う。

---

## 0. 前提・確定事項

- **メニューバーはウィンドウ内で構わない**（2026-08-01 ユーザー確定）。
  macOS ネイティブの上部メニューバー（NSMenu 呼び出しの Objective-C プラグイン）は採用しない。
  → 参考画像と同じ「ウィンドウ内の1行テキストメニュー」を自前描画する方向で確定。
- 実行方式はスタンドアロンビルド（`MonoBehaviour` + `OnGUI`）のまま（editor-spec.md rev.2）。
- 現状の実装場所: `unity/Assets/Scripts/ChartEditorApp/ChartEditorApp.cs`（約1,100行、
  レイアウトは `OnGUI()` 内の固定ピクセル計算）。

## 2. 領域別の詳細差分

### 2.1 メニューバー（新規実装が必要）

| 項目 | 参考 | 現状 |
|---|---|---|
| 存在 | あり（ファイル/編集/表示/プリセット/ウィンドウ/ヘルプ） | **なし** |
| 実現方式 | — | ウィンドウ内自前描画で確定（§0） |

**muses に必要な想定メニュー構成**（案）:

- 表示: エディタ倍率 / バンド境界線の表示 / 判定線位置 / グリッド設定

- ヘルプ: ショートカット一覧 / バージョン情報

IMGUI にはドロップダウンメニュー部品が無いため、**クリックでポップアップ矩形を出す挙動を

## 4. 実装上の技術的論点（次セッション開始時に判断が要る）

### 4.1 IMGUI を継続するか（最重要）→ **UI Toolkit へ移行に確定（2026-08-01）**

ユーザー判断: 「CSSのように扱えるなら」という条件でUI Toolkit移行を選択。USS（Unity Style
Sheets）がCSSのサブセット相当（セレクタ・カスケード・box model・flexboxレイアウト）である
ことが決め手。以下は移行前提で読むこと。

参考の MikuMikuWorld は**見た目からして Dear ImGui 系**（折りたたみヘッダ・ドッキングタブ・
2カラムのプロパティ表は Dear ImGui の典型的な語彙）。Unity の `OnGUI`(IMGUI) も同じ
イミディエイトモードなので**思想は近いが、既製ウィジェットの品揃えが大きく劣る**:

| 必要な部品 | Dear ImGui | Unity IMGUI |
|---|---|---|
| メニューバー | `BeginMenuBar` | **無し**（自前） |
| タブ | `BeginTabBar` | **無し**（`GUILayout.Toolbar` で代用可） |
| 折りたたみヘッダ | `CollapsingHeader` | **無し**（自前 / 現状も 3Dプレビュー・検証結果で自前実装済み） |
| ドロップダウン | `BeginCombo` | **無し**（自前ポップアップ） |
| ドッキング | あり | 無し |
| DPI/倍率 | `FontGlobalScale` | `GUI.matrix` を自前で仕込む |

**選択肢**:
- (a) **IMGUI 継続 + 自前部品を積み増す** — 既存1,100行を活かせる。折りたたみ・タブは
  既に自前実装の前例がある。倍率は `GUI.matrix` のスケーリングで一括対応可能。
- (b) **UI Toolkit（ランタイム）へ移行** — タブ・ドロップダウン・スクロールビューが標準装備、
  USS でスタイリング、DPI 対応も素直。ただし**レイアウト部分は全書き直し**。
  ノーツシートのキャンバス描画は `generateVisualContent` か `IMGUIContainer` で残せる。

**判断の勘所**: 今回の刷新は「レイアウト骨格の作り直し」（§1 の A〜D）なので、
**どのみち `OnGUI()` のレイアウト計算は全面的に書き直しになる**。(b) のコストは
見た目ほど大きくない可能性がある。一方で `PreviewSystem` の `RenderTexture` 埋め込みや
`DrawNotesSheet` の直接描画は IMGUI 前提で書かれており、そこは (a) のほうが安全。
**次セッションの冒頭でユーザーと決める**。

### 4.2 画面倍率の実現方法

`GUI.matrix = Matrix4x4.Scale(Vector3.one * uiScale)` を `OnGUI()` 冒頭で設定すると
全体を一括スケールできるが、**`Screen.width/height` ベースのレイアウト計算も
`/uiScale` する必要がある**（現状 `OnGUI` は素の `Screen.width` を使っている）。
マウス座標（`Event.current.mousePosition`）は `GUI.matrix` 適用後の座標系になるため
ヒット判定は自動で追従するはず（要検証）。

### 4.3 アイコン素材

参考のツールバーはアイコン前提だが、**プロジェクトに画像アセットは1枚も無い**
（[[muses-unity-port-progress]] 記載のとおりノーツ描画も単色クアッドのみ）。
選択肢: (a) テキストのまま横幅を詰める / (b) 簡単な図形をコードで描く /
(c) アイコン素材を用意する。ノーツ素材の作成自体が別軸のタスクとして未着手なので、
**当面は (b) が現実的**。

## 5. 今回あわせて見つかった不具合・宿題

1. **ツールバー2段目が見切れている** — `OnGUI()` の `toolbarH = 44f` に対し、
   `DrawToolbar` は `BeginHorizontal` を2回積んでいる。日本語ラベル「ファイル」が
   2行に折り返している（スクリーンショットで確認可能）ことから、1段目だけで
   44px近くを消費している。**2段目の `幅` / `再生に追従` / `判定線位置` /
   ステータスメッセージが操作不能**。§1 のツールバー再設計で自然に解消する見込みだが、
   それまでの暫定対処として `toolbarH` を上げるだけでも効果がある。

2. **`Display 1 / No cameras rendering` の巨大オーバーレイ** — `PreviewSystem` の
   カメラは `enabled=false` でオフスクリーン `RenderTexture` にのみ明示 `Render()` する設計
   （editor-spec.md §2.2 の負荷対策どおり）。そのため**画面に直接描画するカメラが
   シーンに1台も無く**、Unity がこの警告表示を出している。
   対処案: `ChartEditor.unity` に「何も映さないが `enabled=true`」なカメラを1台置く
   （`clearFlags = SolidColor`、`cullingMask = 0`、`depth` を最背面に）。
   **UI刷新とは独立に直せるので先に潰しておくのが良い。**

3. **app容量120MB の内訳未調査** — 次回ビルド時に `Builds/ChartEditorMac/` 配下と
   ビルドログ（Editor.log の "Build Report" セクション）で内訳を取る。
   削減候補: Managed Stripping Level（現状 `managedStrippingLevel: {}` = 未設定）、
   未使用のグラフィックスAPI、URP のシェーダバリアント、Input System の
   不要パッケージ。**ただし Unity のランタイム自体が数十MB を占めるため、
   劇的な削減は期待しないほうがよい。**

4. **BPM / 拍子 / ソフランを編集する UI が無い** — データ構造（`bpmEvents` /
   `SongMeta.meters` / `scrollEvents`）とシリアライザは実装済みだが、
   エディタから触れない。参考画像ではツールバーのチップ + キャンバス上のチップで
   実現されている。editor-spec.md §2.3「波形 + イベントレーン」が本来の担当箇所で、
   **ここは仕様策定時から一貫して未着手**。

## 6. 次セッションでの進め方（提案、UI Toolkit移行確定を反映）

1. ~~§4.1（IMGUI 継続 or UI Toolkit 移行）~~ → **UI Toolkit に決定済み**。次はUI Toolkitの
   セットアップ（`UIDocument`コンポーネント、ルート`.uxml`/`.uss`一式の新規作成）から。
2. §5-2（No cameras rendering）を先に潰す — 独立して直せる、IMGUIのままでも直せるので
   移行作業と並行/先行どちらでもよい。
3. レイアウト骨格 §1 A〜D を UXML + USS で組む（メニューバー / タブ / トランスポート移設 /
   パネル再編）。`VisualElement`の`flex-direction`等でメニューバー・ツールバー・タブ・
   ステータスバーの各バンドを組み、既存の折りたたみ自前実装は`Foldout`標準要素に置き換え可能。
4. §2 の領域別ディテールを詰める（`TabView`/`DropdownField`等の標準コントロールを活用）。
5. §2.7 設定画面（画面倍率・キーバインド）。UI Toolkitなら`USS`変数(カスタムプロパティ)で
   全体の`font-size`等をテーマ的に一括変更しやすく、画面倍率対応と相性が良い。
6. §5-3 容量調査は独立タスクとしていつでも可。

**移行にあたっての技術的な要点（着手時に確認すること）**:
- `DrawNotesSheet`（ノーツシートの直接描画）と`PreviewSystem`の`RenderTexture`埋め込みは
  UI Toolkitでは`IMGUIContainer`（ノーツシートを当面IMGUIのまま残す）または
  カスタム`VisualElement`の`generateVisualContent`（`MeshGenerationContext`でメッシュ生成）で
  書き直す。**ノーツシートは頻繁な再描画・座標変換が絡むので、まず`IMGUIContainer`で
  包んで動かし、後から余裕があれば`generateVisualContent`に置き換える段階移行が安全**
  （骨格のUXML/USS化を先に済ませ、キャンバス内部の描画方式は後回しにできる）。
- `RenderTexture`埋め込みは UI Toolkit でも`Image`要素の`style.backgroundImage`に
  `RenderTexture`を割り当てれば通常どおり表示可能（IMGUIの`GUI.DrawTexture`から
  ほぼそのまま置き換えられる）。
- ランタイムビルド（スタンドアロン）でのUI Toolkit使用に制約は無い
  （`UIDocument`+`PanelSettings`はランタイム対応の標準機能）。
- 既存の`EnumCycleButton`等の自前クリック循環ボタンは、UI Toolkitの`DropdownField`や
  `EnumField`に置き換えられる箇所が多い。
