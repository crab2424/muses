# muses 譜面エディタ UI 刷新 — 現状と参考画像の差分整理（2026-08-01）

`memory/editor-spec.md` rev.2 で定めた機能はひととおり実装済みだが、**見た目・操作感は
未調整のまま**（[[feedback-editor-ui-polish-deferred]] の方針でここまで指摘を溜めていた）。
ユーザーから参考画像として **MikuMikuWorld**（プロセカ系の譜面エディタ）のスクリーンショットが
提示されたので、実装に入る前に「具体的にどこがどう違うか」を洗い出す。

**このドキュメントは実装計画ではなく差分カタログ**。実装は別セッションで行う。

---

## 0. 前提・確定事項

- **メニューバーはウィンドウ内で構わない**（2026-08-01 ユーザー確定）。
  macOS ネイティブの上部メニューバー（NSMenu 呼び出しの Objective-C プラグイン）は採用しない。
  → 参考画像と同じ「ウィンドウ内の1行テキストメニュー」を自前描画する方向で確定。
- 実行方式はスタンドアロンビルド（`MonoBehaviour` + `OnGUI`）のまま（editor-spec.md rev.2）。
- 現状の実装場所: `unity/Assets/Scripts/ChartEditorApp/ChartEditorApp.cs`（約1,100行、
  レイアウトは `OnGUI()` 内の固定ピクセル計算）。

## 2. 領域別の詳細差分

### 2.1 メニューバー（新規実装が必要）

| 項目 | 参考 | 現状 |
|---|---|---|
| 存在 | あり（ファイル/編集/表示/プリセット/ウィンドウ/ヘルプ） | **なし** |
| 実現方式 | — | ウィンドウ内自前描画で確定（§0） |

**muses に必要な想定メニュー構成**（案）:

- 表示: エディタ倍率 / バンド境界線の表示 / 判定線位置 / グリッド設定

- ヘルプ: ショートカット一覧 / バージョン情報

IMGUI にはドロップダウンメニュー部品が無いため、**クリックでポップアップ矩形を出す挙動を

## 4. 実装上の技術的論点（次セッション開始時に判断が要る）

### 4.1 IMGUI を継続するか（最重要）→ **UI Toolkit へ移行に確定（2026-08-01）**

ユーザー判断: 「CSSのように扱えるなら」という条件でUI Toolkit移行を選択。USS（Unity Style
Sheets）がCSSのサブセット相当（セレクタ・カスケード・box model・flexboxレイアウト）である
ことが決め手。以下は移行前提で読むこと。

参考の MikuMikuWorld は**見た目からして Dear ImGui 系**（折りたたみヘッダ・ドッキングタブ・
2カラムのプロパティ表は Dear ImGui の典型的な語彙）。Unity の `OnGUI`(IMGUI) も同じ
イミディエイトモードなので**思想は近いが、既製ウィジェットの品揃えが大きく劣る**:

| 必要な部品 | Dear ImGui | Unity IMGUI |
|---|---|---|
| メニューバー | `BeginMenuBar` | **無し**（自前） |
| タブ | `BeginTabBar` | **無し**（`GUILayout.Toolbar` で代用可） |
| 折りたたみヘッダ | `CollapsingHeader` | **無し**（自前 / 現状も 3Dプレビュー・検証結果で自前実装済み） |
| ドロップダウン | `BeginCombo` | **無し**（自前ポップアップ） |
| ドッキング | あり | 無し |
| DPI/倍率 | `FontGlobalScale` | `GUI.matrix` を自前で仕込む |

**選択肢**:
- (a) **IMGUI 継続 + 自前部品を積み増す** — 既存1,100行を活かせる。折りたたみ・タブは
  既に自前実装の前例がある。倍率は `GUI.matrix` のスケーリングで一括対応可能。
- (b) **UI Toolkit（ランタイム）へ移行** — タブ・ドロップダウン・スクロールビューが標準装備、
  USS でスタイリング、DPI 対応も素直。ただし**レイアウト部分は全書き直し**。
  ノーツシートのキャンバス描画は `generateVisualContent` か `IMGUIContainer` で残せる。

**判断の勘所**: 今回の刷新は「レイアウト骨格の作り直し」（§1 の A〜D）なので、
**どのみち `OnGUI()` のレイアウト計算は全面的に書き直しになる**。(b) のコストは
見た目ほど大きくない可能性がある。一方で `PreviewSystem` の `RenderTexture` 埋め込みや
`DrawNotesSheet` の直接描画は IMGUI 前提で書かれており、そこは (a) のほうが安全。
**次セッションの冒頭でユーザーと決める**。

### 4.2 画面倍率の実現方法

`GUI.matrix = Matrix4x4.Scale(Vector3.one * uiScale)` を `OnGUI()` 冒頭で設定すると
全体を一括スケールできるが、**`Screen.width/height` ベースのレイアウト計算も
`/uiScale` する必要がある**（現状 `OnGUI` は素の `Screen.width` を使っている）。
マウス座標（`Event.current.mousePosition`）は `GUI.matrix` 適用後の座標系になるため
ヒット判定は自動で追従するはず（要検証）。

### 4.3 アイコン素材

参考のツールバーはアイコン前提だが、**プロジェクトに画像アセットは1枚も無い**
（[[muses-unity-port-progress]] 記載のとおりノーツ描画も単色クアッドのみ）。
選択肢: (a) テキストのまま横幅を詰める / (b) 簡単な図形をコードで描く /
(c) アイコン素材を用意する。ノーツ素材の作成自体が別軸のタスクとして未着手なので、
**当面は (b) が現実的**。

## 5. 今回あわせて見つかった不具合・宿題

1. **ツールバー2段目が見切れている** — `OnGUI()` の `toolbarH = 44f` に対し、
   `DrawToolbar` は `BeginHorizontal` を2回積んでいる。日本語ラベル「ファイル」が
   2行に折り返している（スクリーンショットで確認可能）ことから、1段目だけで
   44px近くを消費している。**2段目の `幅` / `再生に追従` / `判定線位置` /
   ステータスメッセージが操作不能**。§1 のツールバー再設計で自然に解消する見込みだが、
   それまでの暫定対処として `toolbarH` を上げるだけでも効果がある。

2. **`Display 1 / No cameras rendering` の巨大オーバーレイ** — `PreviewSystem` の
   カメラは `enabled=false` でオフスクリーン `RenderTexture` にのみ明示 `Render()` する設計
   （editor-spec.md §2.2 の負荷対策どおり）。そのため**画面に直接描画するカメラが
   シーンに1台も無く**、Unity がこの警告表示を出している。
   対処案: `ChartEditor.unity` に「何も映さないが `enabled=true`」なカメラを1台置く
   （`clearFlags = SolidColor`、`cullingMask = 0`、`depth` を最背面に）。
   **UI刷新とは独立に直せるので先に潰しておくのが良い。**

3. **app容量120MB の内訳未調査** — 次回ビルド時に `Builds/ChartEditorMac/` 配下と
   ビルドログ（Editor.log の "Build Report" セクション）で内訳を取る。

## 7. ディテール実装フェーズの方針（2026-08-01 確定）

§1 のレイアウト骨格（A〜D）は UI Toolkit で実装・実機確認済み。§6 の 3 が完了し、
ここからは §6 の 4（領域別ディテール）に入る。本章はその着手前にユーザーと詰めた
**実装方針の確定分**であり、§1〜§5 の差分カタログを実装可能な粒度まで落としたもの。

### 7.1 判定線より後ろのグリッド・ノーツが描画されない（バグ、最優先）

**症状**: 判定線（`judgeLineFrac`）を下端より上に動かすと、判定線より下の領域に
グリッド線が1本も引かれず、ノーツも途中で消える。

**原因**: `GenerateNotesSheet` のグリッド線ループ（`ChartEditorApp.cs`）が
下方向を1スナップ分しか描いていない。

```csharp
int lineStart = Mathf.Max(0, scrollTick - snapTicks) / snapTicks * snapTicks;
int lineEnd   = scrollTick + L.VisibleTicks + snapTicks;
```

`TickToY` は下に行くほど tick が小さくなる（`judgeLineY - (tick - scrollTick) * pxPerTick`）ため、
判定線より下の領域は `scrollTick` **未満**の tick に対応する。ところが開始点が
`scrollTick - snapTicks` しかないので、判定線の1スナップ下から先は描画対象外になる。
ノーツが消えるのも同じ原因で、culling 条件 `nEnd < scrollTick - snapTicks * 4` が
判定線の4スナップ下で切っている。小節番号ラベル（`ChartEditorApp.UI.cs` の
`UpdateSheetLabels`）にも同じ式が入っている。

`judgeLineFrac` の既定値が 1.0（判定線が下端）なので、スライダーを動かすまで顕在化しなかった。

**修正**: `VisibleTicks` を廃止し、`SheetLayout` に上下端の tick を持たせて上記3箇所を置き換える。

```csharp
public int TopTick    => scrollTick + Mathf.CeilToInt((judgeLineY - rect.y)    / pxPerTick);
public int BottomTick => scrollTick - Mathf.CeilToInt((rect.yMax - judgeLineY) / pxPerTick);
```

他の項目と独立して直せるので**最初に潰す**。

### 7.2 帯構成の変更（左右余白の確保）

現状 `SheetLayout` は幅を `Ground | ガター26px | Sky` で使い切っており、
参考画像のようなレーン外の余白が無い。その結果**小節番号をレーン内左端に重ねて描いている**
（§2.4 の指摘そのもの）。余白を作ることで置き場ができる。

| 帯 | 幅 | 用途 |
|---|---|---|
| 左余白 | 44px | 小節番号（レーン外へ退避、§2.4 解消） |
| Ground | 可変 | 12セル |
| ガター | 26px | 現状維持 |
| Sky | 可変 | 12セル |
| **高さレーン** | 0 / 約100px | §7.5。既定は折りたたみで0px |
| 右余白 | 104px | イベントレーン（§7.3） |

ウィンドウ幅1290pxでの試算: 高さレーンを畳んだ状態でセル幅 52.7px → 46.5px（約12%減）。
高さレーンを開いた状態で 42.4px。**Slide の中継点操作に支障が出るほど狭くはないと判断**したが、
実機で窮屈に感じたら右余白（イベントレーン）を折りたたみ可能にする余地を残しておく。

### 7.3 イベントレーン（§5-4 の機能欠落を解消）

BPM・拍子・ソフランを**エディタから編集できない**という §5-4 の欠落に対応する。
データ構造（`ChartData.bpmEvents` / `SongMeta.meters` / `ChartData.scrollEvents`）と
シリアライザは実装済みで、UI だけが無い状態。

- **表示**: 右余白に各イベントを tick 位置の y にチップとして描く。判定線の行には
  参考画像と同じく**現在値を常時表示**（`160 BPM` / `4/4`）。これは §2.6 の
  「カーソル位置の拍子・BPM がわからない」も同時に解消する。
- **操作**: レーン空白をクリック→種別選択して追加 / チップをクリック→右パネルの
  インスペクタで値編集 / チップをドラッグ→tick 移動 / Delete→削除。
- **実装**: Painter2D は文字を描けないため、既存の `PlaceSheetLabel` プール方式を拡張した
  `Label` 要素として置く。要素側でポインタイベントを受けられるので、チップの
  クリック判定を自前でやらずに済む点でもこちらが有利。
- **設計上の注意（重要）**: **BPM・拍子は `song.muses`（全難易度共通）、ソフランは
  難易度別ファイル**に属する。同じレーンに混ぜると「今どのファイルを編集しているか」が
  見えなくなるため、チップの色を3種で明確に分け、BPM/拍子の編集時には
  「全難易度に影響する」ことを UI 上で示す。
- 拍子（`METER`）は小節先頭にしか置けないはず。`ChartValidator` に該当ルールが
  あるか着手時に確認し、無ければ追加する。

**実装済み（2026-08-01、コミット時点）**: 上記方針から以下の点を実装時に具体化・変更した。

- **列自体を種別選択に使う**: 右余白(104px)を BPM/拍子/ソフランの3等分の列に固定した
  （`EventColumns()`）。これにより「クリック後に種別を選ぶメニュー」は不要になった
  （列を選ぶことが種別選択を兼ねる）。将来イベント種別が増える場合はこの前提が崩れる点に注意。
- **チップのドラッグ移動は見送り**: 位置編集はインスペクタの「位置」テキスト欄
  （ノーツの中継点と同じ `bar:beat:tick` 形式）で行う。ノーツの位置編集も元々ドラッグと
  テキスト入力の両対応だったため、テキスト入力だけでも編集不能にはならない。ドラッグは
  次回増分で追加候補。
- **拍子(METER)の重複防止**: 同じ小節に拍子イベントが既にある場合、追加ではなく既存の
  ものを選択する（`song.meters.FindIndex(m => m.bar == bar)`）。小節头以外に置けない制約は
  `MeterEvent.bar`（int、小節番号のみを持つ）というデータ構造自体が保証しており、
  `ChartValidator` 側にルールを追加する必要はなかった。
- **重要な発見（Undoの対象範囲）**: `UndoSnapshot` は `chart`（`ChartData`）と `header` のみを
  保持し、**`song`（`SongMeta`）は元々Undo対象外**だった（既存のタイトル/アーティスト等の
  編集も同様に非対応）。そのため BPM/拍子イベント（`song.bpmEvents`/`song.meters`）の追加削除は
  既存の song.muses 系フィールドと同じく `PushUndo` を呼ばない実装にした
  （呼んでも無意味などころか、直前の無関係なchart編集を巻き戻してしまう副作用がある）。
  ソフラン(`chart.scrollEvents`)は`ChartData`の一部なので通常どおり`PushUndo`する。
  **How to apply**: 今後 `song.*` に対する編集機能を追加するときは、Undo が効かないことを
  前提に設計する（元に戻せない旨をUIで示す、または別途song用のUndoスタックを設ける、の
  どちらかは次回の課題として残っている）。

### 7.4 マウス操作の拡張

現状は「クリック配置 / クリック選択＋ドラッグ移動 / Delete / ホイールスクロール /
Ctrl+ホイールズーム」のみ。優先度順に:

**A. 矩形選択と複数選択（最優先）**
- 選択ツールで**空白からドラッグ**した場合が現在未使用なので、そこに割り当てる。
- `selectedNote`（単一）を `List<Note> selection` + primary に変える必要がある。
  インスペクタは**単一選択時のみ従来表示**、複数時は「N件選択」＋一括操作
  （削除／種別変更）に留める。
- Slide は waypoint の一部でも矩形に掛かれば選択。
- Shift+ドラッグ=追加選択、Shift+クリック=トグル。
- 複数選択のドラッグは tick 差分・cellF 差分をまとめて適用
  （既存の `dragOriginPoints` 方式をリスト化）。

**B. ドラッグ移動の層跨ぎ対応（現状の欠陥）**
`OnSheetPointerMove` は `PaneAt` の戻り値のうち `layerF` を捨てて `cellF` 差分しか
使っていない。Ground のノーツを Sky ペインへドラッグしても層は変わらず、
cellF だけが飛ぶ。ペインをまたいだら `layerF` も更新する。

**C. コピー／カット／ペースト** — Cmd/Ctrl+C/X/V。内部クリップボードで十分
（OS クリップボード連携は不要）。貼り付け基準 tick は判定線位置。

**D. 端ドラッグで幅変更** — ノーツの左右端 ±4px でつかむ。editor-spec.md で
意図的に省いていた項目。

**E. 右クリック→コンテキストメニュー** — 削除／種別変更／中継点追加。
メニューバーで `GenericDropdownMenu` が実機で動作確認済みなので流用できる。

**F. Alt+ドラッグで複製、中ボタンドラッグでパン** — 優先度低。

**Undo との整合ルール**: ドラッグ開始時に1回だけ `PushUndo(coalesce: false)` し、
移動中は積まない。

**実装済み（2026-08-01、A〜E。Fは優先度低のため見送り）**。方針からの変更点:

- **`selectedNote` は消さず、`selection`（実体）＋ 同期用の後方互換フィールドという構成**にした。
  `selection.Count == 1` のときだけ `selectedNote` が実体を指し、それ以外は `null`。
  こうすると既存の単一選択前提のコード（インスペクタ・中継点追加・ステータスバーの
  `BuildChartInfoText`）が**そのまま複数選択時に無効化される**ので、呼び出し側を書き換えずに済んだ。
  同期は `SyncSelectedNoteFromSelection()` に集約している。
- **D（端ドラッグで幅変更）は単発ノーツ限定**。Slide は `width` が中継点ごとの値で、
  帯のどの区間を掴んだかで対象の中継点が変わるため、素直な「左右端をつかむ」操作に落ちない。
  Slide の幅はインスペクタの中継点ごとの `width` で編集する（従来どおり）。
- **選択済みグループの一員をクリックしたときは選択を維持する**（単一選択に落とさない）。
  これをしないと複数選択したものをまとめてドラッグできない。
- 矩形選択の当たり判定は**中継点(waypoint)単位**。Slide は帯の途中だけが矩形に掛かっても
  選択されない（方針の「waypoint の一部でも矩形に掛かれば選択」どおりだが、
  *帯*ではなく*点*が基準である点は実際に触ると気づきにくいので明記しておく）。

### 7.5 Ground/Sky を跨ぐ Slide の「高さ」表現

**表現方式（縦=時間、横=layerF を左0〜右1で線形）はそのまま採用。
ただし別タブではなく、タイムライン内の折りたたみ可能なレーンとして実装する。**

**なぜ高さ専用の軸が要るか**: 現状 `SheetLayout.CombinedX` は `layerF` で Ground/Sky
両ペインの x を lerp している。つまり**横軸1本に cellF と layerF が混ざっており、
遷移中の高さが読めない**。高さ専用の軸を立てるのは正しい解。
ユーザーの「3Dステージを正面左から投影して90度時計回りに回転」という説明も、
縦=時間・横=高さという写像として整合している。

**タブ案が出た理由と、その再検討**:
ユーザーは「同じタイムラインに置くと窮屈になる、横スクロール導入は実装コストが高い」
という理由でタブを提案した。これは妥当な懸念だったが、**ユーザー自身が発見した
「同時押し Slide で高さの動きが重なると1レーンでは編集できない」という欠陥**が
判断を変えた。

- **重なり問題はタブでも同じように起きる。** 同時押し Slide が2本とも同じ高さ遷移を
  すれば、タブに分けても曲線は完全に重なる。つまり**選択・レイヤーによる絞り込みは
  形式によらず必須**であり、タブを選ぶ理由にはならない。
- **絞り込みを入れると窮屈さの前提が変わる。** 表示するのが選択中の1〜2本だけなら
  必要な幅は100px程度で済み、**折りたたみ可能にすれば既定では0px**。
- **実装コストもレーンのほうが安い。** タブは独立した描画パス・スクロール同期・
  入力処理が丸ごと必要になるのに対し、レーンは既存 `SheetLayout` の y 軸を
  そのまま使えるので、描画とヒットテストへの分岐追加で済む。

**確定仕様**:
- §7.2 の帯構成に幅約100pxの高さレーンを追加。左端=0(Ground)、右端=1(Sky)。
- **既定は折りたたみ（幅0）**。「表示」メニュー or 右パネルの表示設定でトグル。
- **選択追従**: 選択中のノーツの waypoint のみを折れ線＋点で描く
  （＝ユーザーの言う「高さレーン独自のレイヤー切り替え」を、選択状態で代用する）。
  非選択のノーツは描かないか極薄で背景として描く。
- waypoint を横にドラッグして `layerF` を直接編集できるようにする。
  現状は右パネルの数値入力のみで、Slide の高さカーブを作るのは相当な手間になっている。
- **ガターを流用しない**理由: `CombinedX` の lerp の軌跡はガター上を通らない
  （両ペインの同一 cellF 間を結ぶため）。同じ画素に2つの意味が重なるので、
  独立したレーンとして分離する。

**優先度は本章の中で最後**。3Dプレビュータブで見た目の確認自体はできており緊急性はない。
価値は「高さカーブを正確に編集できる」ことにある。

**実装済み（2026-08-01）**。確定仕様どおり。実装時に決めた細部:

- **単発ノーツ(Tap/Ex Tap/Flick)は高さレーンでも掴めるが、`layerF` は 0/1 にスナップする**
  （Ground/Sky のどちらかにしか存在できないため）。Slide の中継点だけが連続値を取る。
  これにより「高さレーンから Tap を Ground↔Sky へ移す」操作が副産物として得られた。
- easing 区間は約6px刻みの折れ線で近似する。`easing == Linear` または両端の `layerF` が
  同値なら分割しない（直線なので）。
- 斜め線を描く必要が出たため `FillLine`（法線方向にオフセットした四角形を塗る）を追加した。
  Painter2D の stroke 系APIを使わないのは、このファイルの他の描画と同じ
  「塗りつぶしパスのみ」に揃えるため。
- 判定線は高さレーンの右端まで伸ばす（同じ時間軸なので、そこで途切れると読みにくい）。
